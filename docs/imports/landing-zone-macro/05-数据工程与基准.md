# 05 数据工程与基准

## 1. 三层库表设计（MySQL，设计 v1.3）

三个需求互相冲突：采购期指标频繁增减（要求加指标不改表）、协方差计算（要求行=日期、列=资产）、LLM 月报（要求一行=一个月全部指标）。解法是分层：

| 层 | 表 | 形态 | 作用 |
| --- | --- | --- | --- |
| Layer 0 | `indicator_catalog` | 目录 | 全部指标元数据（含义、单位、来源、频率、分类）的唯一权威来源，外键约束所有数据表；内部衍生特征同样登记（`data_source='INTERNAL_CALC'`） |
| Layer 1 | `macro_monthly`、`macro_daily`、`market_daily`、`quant_daily`、`derived_daily`、`central_bank_events`、`news_raw` | 窄表（指标 + 时间 + 值 + 版本） | 按频率／类型分表，写入灵活，新增指标只需 INSERT |
| Layer 2 | `macro_snapshot_monthly` | 宽表（约 35 列） | 每月聚合一次，一行即一个月快照，供 LLM／报告直接读 |

设计原则：

1. 按频率分表，不混存。
2. 原始层窄表、聚合层宽表，月度脚本同步。
3. 格式转换（pivot）放 Python 层，对调用方透明。
4. catalog 是唯一真相来源；LLM 可联表取指标语义。
5. 原始文件留在文件系统，不入库；靠命名规范溯源（`{batch}_{YYYYMMDD}.xlsx`，日期是导出日不是数据截止日）。
6. 需要「日频原始 + 月度聚合」的指标，两份都存，保证可复算到日频。
7. 修订追加 `data_version`，不覆盖；日转月聚合标 `source_tag='AGG_FROM_DAILY'`。

**实际状态**：DDL 与种子数据已写，但大部分 ETL loader 是 `NotImplementedError` 桩，宽表存储过程未跑通；宽表还包含从未采集的列（EPU、GPR、美国 5 年通胀预期、北向资金等）。月报实际走「Python 脚本加工 Excel → CSV → 拼接提示词」。

> 对 invest-lab 的参照价值：catalog 作单一真相、窄表写宽表读、修订不覆盖，与 invest-lab 的「资料清单单一写入、已引用版本不覆盖」一致；但 invest-lab 要求的发布日期／版本／截点证明，原设计**没有字段承载**，迁移时须补。
