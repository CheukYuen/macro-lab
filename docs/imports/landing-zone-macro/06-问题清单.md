# 06 问题清单

萃取时发现的问题，按对复用的影响排序。每条给出依据与修正建议；修正均未实施。

## 高

### H1 预期收益直接用历史均值

- 依据：年化 μ 在 12M 窗口另类 38.5%、股票 22.0%；60M 窗口股票 2.5%、另类 20.6%（`02` §4.1）。
- 影响：直接进 MVO 会得到极端、随窗口剧烈跳动的权重；另类收益被 2025–2026 黄金单边行情主导。
- 建议：μ 改为①市场均衡隐含收益（反向优化）+ BL 观点；或②积木法：现金 = 当前短端利率，债券 ≈ 当前到期收益率，股票 = 无风险利率 + ERP（ERP 明示依据），黄金／商品给保守假设；③至少对历史均值做收缩并设上下限。σ、ρ 可继续用长窗口历史估计。

### H2 无风险利率口径只适合短期 Sharpe

- 依据：rf 统一取 CGB_1Y；现金腿 Sharpe 3.35（波动接近 0，比率无意义）；1Y 窗口只有 12 个样本。
- 影响：直接用于股权估值会低估折现率（2026-03：1Y 1.26%，10Y 1.83%）。
- 建议：短期绩效评价用 1Y；DCF／股权估值按现金流期限与币种匹配，人民币资产通常取 10Y 国债（invest-lab `SPEC.md` 已规定中债官网 10Y 为候选）。现金腿不报 Sharpe；Sharpe 窗口至少 36M。

### H3 未经验证的量化结论混在框架文档中

- 依据：原项目「资产决策信息指标」材料中的「动态调仓超额收益约 5.56%」「连续三期 PPI 超预期后商品胜率 68%」「PPI 预期与原油相关 0.73」「油气与美股负相关 -71.8%」「社融超预期后 AI 板块上涨 13.46%」等，均无出处、样本期与回测。
- 建议：一律视为待验证假设；未经本项目回测不得进入研究结论或提示词。

### H4 文档与代码口径前后矛盾

| 项目 | 文档 A | 文档 B／代码 |
| --- | --- | --- |
| 收益率 | 采购清单：对数收益 `ln(P_t/P_{t-1})` | 建模代码：简单收益 |
| 债券因子 | 采购清单：`-D × ΔCGB_10Y` | 方案 B：`ΔCGB_3Y` |
| 窗口 | 设计：含 180M | 代码：无 180M |
| 无风险利率汇总 | 设计：rf_current/1y/…/20y | 实际产出：只有季末序列 |
| 命名提示词 | skill README 中贴的提示词（更严格，含示例） | 实际提示词文件（较宽松） |
| 日转月 | 提示词：月均 | 建模：月末（有意为之，但未在一处统一说明） |

- 建议：以代码为准，在定义层统一登记；复用前逐项选定一种。

### H5 测评闭环与真实任务错位

- 依据：评分标准要求「方向／仓位比例／时间窗口／重点与规避板块」与技术面分析，而月报提示词明确禁止给具体比例；评测用虚构的 demo 市场数据；仅 3 条测试查询；打分与改写提示词由同一模型完成。
- 影响：迭代会把提示词推向评分标准的偏好，而不是月报目标；同一模型自评自改存在迎合评测者的风险；样本过少易过拟合。
- 建议：评分维度从任务规格派生；用真实数据与固定测试集；评测与优化分属不同模型，或至少保留人工抽检；新增「约束遵守」维度（如不得给比例、不得引用未提供数据）。

### H6 数据无截点与版本信息

- 依据：原始文件只有导出日期（文件名中的日期是导出日，不是数据截止日）；指标值无发布日期、无版本；当月未结束时的月均值是部分月份均值且未标注。
- 影响：不满足 invest-lab「截点按披露／版本时间判断、修订不倒灌」的要求；附录数值只能作为候选。
- 建议：迁移时每个序列记录发布日期、取得时间、供应商查询参数与版本；部分月份单独标记或剔除。

### H7 数据库设计与实际链路脱节

- 依据：ETL loader 多为桩代码，宽表未跑通；宽表包含从未采集的 EPU、GPR、美国 5 年通胀预期、北向资金等列。北向资金自 2024-08 起不再按日披露净买入，该列即使采集也无法延续。
- 建议：不迁移库表实现，只借鉴分层原则（`05`）；任何列先确认取数渠道可持续再设计。

## 中

### M1 `PMI_SERV` 实为非制造业商务活动指数

- 依据：所用 Choice ID EMM00122009 原名「中国:非制造业PMI:商务活动」；但 ID 叫 `PMI_SERV`、文档写「服务业PMI」，银行清单写「非制造业PMI:服务业」。
- 建议：改名 `PMI_NON_MANU`，或改取服务业商务活动指数并核对代码。

### M2 进出口币种未核实

- 依据：ID 为 `EXPORT_AMOUNT_CNY_YOY`，Choice 原名「中国:出口金额:同比」未标币种；需求文档写「出口增速（美元计价）」。2026-02 出口同比 +36.1% 未注明是否 1–2 月合并或基数效应。
- 建议：按 Choice ID 核对币种；喂数时对春节错位、基数效应、1–2 月合并加注释。

### M3 新闻样本违反自身规范

- 依据：样本标题「霍尔木兹海峡通行受扰 国际油价大涨」写了市场反应；第二条把工信部政策与大模型 token 用量两件事合在一条；`context` 中夹带「新闻中同时出现了……三部分信息」这类加工者描述；`sentiment_label` 未说明是对哪类资产而言（油价上涨对另类正面、对权益负面）；最终 schema 删除了 `source`、`datetime`。
- 建议：情绪按资产给方向（如 `impact_direction: {另类: +, 权益: -}`）；恢复来源与发布时间以满足溯源。

### M4 事件引擎只服务大类资产

- 依据：P0 筛选明确丢弃个股／单行业新闻。
- 建议：行业／公司研究另设事件层级（宏观／行业／公司），沿用「单跳、可验证、有市场验证」的规则。

### M5 indicator_id 的「两轮一致」不等于理解

- 依据：两轮同模型、共享示例，一致性部分由示例决定（`03` §3.2）。
- 建议：增加跨模型往返测试；以「另一模型能否从 ID 还原含义与口径」作为验收标准。

### M6 月报未提示的数据陷阱

- 1–2 月合并发布导致 1 月空值、累计同比在年初跳变（如基建累计同比 2025-12 为 -2.2%，2026-02 为 +11.4%）。
- M1 自 2025-01 起统计口径扩容，跨期比较有断点。
- 已定义的期限利差、信用利差、CPI−PPI 剪刀差没有喂给模型，模型需自行相减，易出错。
- 建议：在口径段写明这些断点；直接喂衍生利差。

### M7 四模块结构未落地

- 依据：设计了「各模块先产出 JSON 再汇总」，实际是把约 400 行原始数据一次性塞进提示词。
- 建议：先按模块做预消化（状态、趋势、驱动、资产影响），再汇总判断；既缩短上下文，也让中间判断可审计。

### M8 另类资产 70／30 权重缺依据

- 依据：`0.7 × 黄金 + 0.3 × 商品` 无推导，隐含每月再平衡。
- 建议：说明权重来源（如产品池实际暴露），或黄金、商品分列为两条腿。

## 低

- 12M 相关矩阵只有 12 个样本，不宜作为配置输入。
- `LPR_1Y` 来源在不同版本分别标 PBOC 与 CFETS（报价由全国银行间同业拆借中心发布）。
- `AA_CREDIT_YIELD_3Y` 实为中债**企业债** AA 3Y，命名应体现。
- 银行分类中「股债混合（股 20%–50%）」归入股票类，与常见口径（偏债混合属固收+）不同，使用时注意映射。
