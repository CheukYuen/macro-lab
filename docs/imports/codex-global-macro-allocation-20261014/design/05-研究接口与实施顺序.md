# 研究接口与实施顺序

资产配置以组合的长期回报和风险为终点；行业与公司研究以具体业务的量、价、利润和现金流为终点。两者共享有版本的宏观证据，并分别解释采用方式。

## 1 共用事实而保留不同决策

| 层 | 负责回答 | 交给下游的内容 |
| --- | --- | --- |
| 宏观证据与状态 | 增长、通胀、融资和制度环境怎样变化，市场预期是什么 | 地区状态、结构趋势、情景路径、发布与修订、价格隐含条件和不确定性 |
| 资产配置 | 哪些现金流和风险补偿值得在既定约束下持有 | 各资产长期收益假设、风险、候选配置、币种对冲及中期偏离理由 |
| 行业 | 哪些需求池受影响，供给能否响应，价格与利润如何传导 | 产品/地区的量价、有效供给、竞争、时滞、反证 |
| 公司 | 该公司实际暴露有多大，多少收益能转成股东现金 | 分部收入、成本与利润、资本开支、营运资金、资本结构、估值采用 |

宏观状态不是交易指令，配置权重也不是公司估值参数。例如“宏观环境支持股票”不能直接推出某公司收入增长；“美债预期回报较好”也不能用来调低人民币公司的折现率。

全球政策环境尤其不能用一个全球流动性分数代替。不同国家的汇率制度、金融深度、外币负债和政策空间会改变同一美元冲击的传导。IMF 的综合政策框架可作为这一差异化设计的方法依据，不作为资产涨跌预测。[IMF Integrated Policy Framework](https://www.imf.org/en/topics/ipf-integrated-policy-framework)。

## 2 传导矩阵

| 宏观变化 | 资产配置研究重点 | 行业中间环节 | 公司可采用的参数与条件 |
| --- | --- | --- | --- |
| 实际需求改善 | 权益盈利、周期商品、信用损失；同时比较价格已反映多少 | 地区终端订单→库存→产能利用率 | 销量/订单兑现；须证明产品和客户暴露 |
| 工资与服务通胀粘性 | 实际利率和政策路径、债券久期、权益估值压力 | 用工成本、服务价格转嫁和自动化投资 | 人工成本、售价、费用率；不能用总 CPI 替代 |
| 能源供给冲击 | 商品、通胀挂钩债、名义债与风险资产共同压力 | 能源进口依赖、投入品、运输及替代 | 成本、售价传导、对冲和库存时滞 |
| 信用扩张或紧缩 | 利差、违约、融资与流动性风险 | 下游融资能力、设备采购、经销商库存 | 订单、坏账、应收账款天数与融资成本 |
| 财政投资增加 | 供给和需求影响、发债与期限溢价 | 项目立项→资金到位→实物施工→产品采购 | 收入确认、回款、资本开支与营运资金；发行专项债不等于收入 |
| 美元走强或融资紧张 | 外汇敞口、美元融资、跨国资产估值 | 进口成本、出口竞争力、外币债务及定价货币 | 交易/折算/经济敞口分别映射；看净敞口而非只看海外收入 |
| AI 或电网投资扩张 | 投资主题集中度、长期盈利与高估值风险 | 资本开支拆分→设备/线路/电力需求→认证和交付 | 对应产品份额、产能、ASP、投入资本；不能总 Capex 直接乘公司收入弹性 |
| 关税与贸易制度改变 | 国家/行业集中、风险溢价和流动性 | 适用产品、原产地、供给迁移、客户转单 | 收入/成本/迁建开支；公告、实施、豁免和过渡日期分开 |

传导表是待研究路径，不是固定符号表。同一个价格变化可能来自需求、供给或风险补偿变化，采用前须辨认原因。无法量化的环节允许保留定性判断，不用任意弹性填满公式。

## 3 交接内容和情景映射

新的配置设计建议使用通用情景概念：基准、需求扩张、需求衰退、供给型通胀、融资或流动性压力，并按需要加入结构主题。它们是可组合的冲击描述，只有在明确互斥且穷尽的模型中才赋总和为 1 的概率；独立压力测试不用凑成概率分布。

现行首轮 `SPEC.md` 的 `capex_up / base / capex_down` 保留。未来若用于长飞，每个 Capex 情景单独说明来自哪些宏观路径、哪些变量保持不变、哪些变量仍未确定；不能把“全球需求扩张”直接等同于“AI Capex 上行”，不能将通胀高低机械绑定 Capex。

| 交接字段 | 说明 |
| --- | --- |
| `object_id, version, cutoff` | 地区/主题与确切版本；日期不沿用另一研究任务 |
| `evidence_refs` | 指向稳定证据 ID 和原始资料定位，不复制多份独立原值 |
| `state_and_trend` | 水平、变化、加速度、预期差分开；带区间或置信说明 |
| `scenario_paths` | 年度/季度变量路径、机制、触发信号、反证；定性路径明确标示 |
| `market_pricing` | 当前价格隐含哪些条件；采用的模型、期限和币种 |
| `transmission_map` | 影响地区/产品、机制、时滞、方向的条件、是否有量化依据 |
| `adoption_record` | 下游采用/调整/不采用哪些输入及原因；谁决定参数 |
| `limitations_and_update` | 缺口影响、失效条件、下一次有意义的更新事件 |

宏观作者给环境与证据；行业作者给产品传导；公司作者选择经营参数和期限/币种匹配的估值输入。若未来接入 `research/`，仍使用现有 `handoff.md / drivers.json / selfcheck.md` 和原作者修订规则，不因本设计另立并行交接制度。

## 4 教学例子

假设某国宣布增加基础设施预算。配置层首先研究支出能否兑现、发债是否推高长期利率，以及相关资产是否已上涨反映这一变化。行业层进一步拆分资金投向、施工进度、产品需求与现有库存。公司层再检查其销售地区、产品认证、订单、付款条件及产能。

即使最终收入增加，公司也可能因为原材料涨价、客户回款慢或扩产支出而自由现金流减少。这说明宏观改善可以同时支持收入判断并压低现金转化；配置模型不能把每层都简化成同方向加分。

## 5 从旧框架迁移的决定

| 旧设计 | 新设计决定 | 理由 |
| --- | --- | --- |
| 中国宏观为主，海外仅黄金/原油/VIX | 中美完整面板，其他地区共同面板加专题 | 经济周期、通胀、汇率和资产回报跨国不同步 |
| 每个维度只留一个指标 | 研究池可交叉核实，入模按增量信息控制冗余 | GDP、生产和调查反映不同时间与覆盖，不能先验互相替代 |
| 历史至少 10—20 年才入池 | 区分监测、估计和配置资格 | 新制度/新资产有研究价值，短样本风险应透明而非伪造历史 |
| 四模块固定映射资产涨跌 | 经济状态、预期与估值、风险和交易约束分层 | 同样的增长信号在不同定价与政策条件下可能有不同回报 |
| 四条资产腿与黄金/商品 70/30 | 按现金流、风险因子和实施工具拆分 | 避免未经依据的内部权重与风险混合 |
| 12—240 月历史均值直接作 μ | 各资产收益分解、区间与情景；历史均值只作诊断 | 估计窗口变化不应直接决定未来最优仓位 |
| 全部资产一套无风险利率 | 币种/用途/期限匹配 | 现金绩效、美元资产回报和人民币 DCF 不是一个问题 |
| 最后修订数据用于历史模型 | 按真实发布和版本截点形成快照 | 防止修订信息与前视偏差 |
| 全部共同样本、单一相关矩阵 | 核心矩阵、因子扩展和压力相关并列 | 避免短历史资产限制全池，允许股债相关性改变 |
| LLM 从原始表直接给方向 | 先确定可复算特征与证据，再解释和提出待验证观点 | 模型叙述不替代计算、校准与反证 |

不迁移旧文档中的参数快照、历史数值、未核实胜率或原 ETL；旧导入材料继续保留其候选参考身份。

## 6 后续实施次序

以下是本轮设计交付后的建议次序，需要另行启动；不表示本轮已开始取数或实施。

| 阶段 | 最小工作 | 交付与通过条件 |
| --- | --- | --- |
| 1 选择组合任务 | 确定人民币/美元各一个账户边界，选典型约束模板，明确负债与流动性要求 | 冻结目标、资产范围、基准、币种与约束，接受/暂缓项目清楚 |
| 2 验证少量数据样本 | 覆盖中美宏观发布/修订、股债总收益、FX 对冲、商品展期、一个短历史资产 | 定义可追溯、版本能重建、口径能复算；失败项退出该轮输入 |
| 3 建最小战略基线 | 小型流动资产池，长期收益分解、简单风险基线、几种约束下的候选组合 | 收益/风险/币种/现金账一致，参数敏感性和压力损失有解释 |
| 4 验证增量模型 | 逐个加入收缩风险、宏观状态或有限中期偏离 | 相对简单基线有稳定且净费后的价值；否则保留解释用途 |
| 5 加入实施限制 | 将研究资产映射至可用工具、账户、成本、容量和保证金 | 理论与可实施结果并列，跟踪偏差与约束代价可解释 |
| 6 接行业公司 | 选择一条真实传导链验证输入引用、采用、反馈与更新 | 行业/公司实际消费确切宏观版本，不凭宏观结论生成公司数字 |
| 7 扩充卫星资产 | 私募/策略/数字资产按独立数据和流动性资格逐项进入 | 现金流、估值滞后、尾险、容量和额外复杂度可证明合理 |

本设计先形成可审阅方案，不替换 invest-lab 首轮实施顺序。若将资产配置扩展为项目正式目标，后续应明确更新 SPEC 中的目标、情景、角色和完成标准；设计文件本身不构成规格变更。

## 7 文档与运行边界

本设计目录是独立的新版本提案。接受后若改变模型、资产定义、币种或约束，记录变更理由和受影响的下游；尚未接受前可以根据审阅修订。正式研究包一旦被采用则继续遵守现有冻结版本规则。

完成详细设计只说明指标、资产、方法和验证路径已经表达清楚。后续是否形成配置建议，取决于真实输入、具体约束和验证结果；本轮不提供当前仓位建议或声称任何模型已经有效。
