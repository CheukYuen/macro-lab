# 03 提示词工程

原项目的 LLM 链路：qwen3-235b 生成中国市场月报，Claude／多模型评测并迭代提示词。本文件整理四件事：逆向工程方法、指标命名、喂数格式、评测闭环。

## 1. 逆向工程：让模型暴露隐含知识

不直接问模型要答案，而是逼它说出隐含的常识、假设与决策逻辑，再抽象成可执行的规则和所需数据。原项目用于「客户资产亏损时系统如何处理」，方法本身与题目无关。

### 1.1 提问四原则

1. 不让模型直接给结论或建议（避免套路话术）。
2. 强迫区分对象（原题：资产／人／系统；估值场景可换成：宏观／行业／公司）。
3. 要求分阶段、分状态回答，而非一次性回答。
4. 要求解释「为什么这样处理」，而非「该不该做」。

### 1.2 提问序列

| 步骤 | 目的 | 原题示例 |
| --- | --- | --- |
| P0 角色校准 | 换掉默认的「顾问」人设 | 「你不是投资顾问，而是金融决策系统设计专家……从风险控制、行为金融、系统设计角度回答」 |
| P1 第一性原则 | 看模型优先保护什么、目标函数是否切换 | 亏损后最优先保护什么？关注对象如何排序？为何继续优化收益是危险的？ |
| P2 状态划分 | 逼出隐含状态机 | 把亏损拆成多个阶段，逐阶段给目标、最危险行为、多做／少做什么（表格） |
| P3 何时少干预 | 区分成熟系统与表层话术 | 哪些阶段应减少建议？为何信息越多反而有害？ |
| P4 分类差异 | 建差异化规则的底稿 | 现金／固收／权益／另类各自亏损的含义、风险来源、常见错误（表格） |
| P5 可忍 vs 必须警惕 | 正常波动 vs 结构性问题 | 哪些亏损可预期？哪些意味着不可逆风险？如何区分？ |
| P7 规则化 | 把回答压成工程语言 | 抽象为可执行规则、可识别信号、必须限制的行为（中性、工程化、表格） |
| P8 多角色收敛 | 稳定逻辑 = 多视角共识 | 分别站在风控、行为金融、系统工程、合规视角回答，比较共识与分歧 |

产出目标是四类素材：**状态、触发条件、风险信号、系统护栏**。原项目在 P8 之后再追问「这些角色各自需要什么信息」，得到分层的输入指标清单（情绪认知 → 行为意图 → 资产组合健康度 → 环境归因），即「由模型反推所需数据」。

### 1.3 迁移示例（估值场景，未实际运行）

```text
P0：你不是卖方分析师，而是投资研究流程的设计者。
P2：把一个行业从需求启动到产能过剩拆成若干状态；每个状态下，判断公司盈利与估值最关键的
    3 个宏观/行业变量是什么？哪些变量最容易被误用？
P8：分别以宏观策略、行业研究、信用分析、估值建模视角回答，比较共识与分歧。
追问：为做出上述判断，每个角色需要哪些数据？列出频率、口径与可替代指标。
```

## 2. 指标「逆向」：原始指标 → 模型可读指标

| 类别 | 处理 | 指标 |
| --- | --- | --- |
| A 直接喂原值 | 同比、累计同比、50 阈值、指数水平本身有经济含义 | GDP、M1、消费者信心、新出口订单 PMI、进出口同比、投资累计同比 |
| B 先月度化 | 日频价格／利率转月均或月末 | 布油、黄金、DR007、AA 3Y、国债 3Y |
| C 先派生 | 累计值转进度／当月新增／同比；年度目标作分母 | 专项债累计发行 + 年度目标 → `SPECIAL_BOND_PROGRESS` |

判断某原始指标是否还需「逆向」：供应商代码感太强、代码过短语义不足、原名与喂给模型的表达之间还隔一层业务解释、频率或形态（日度／累计／年度目标）不适合月度判断。

## 3. indicator_id 命名

### 3.1 规则

| 规则 | 示例 |
| --- | --- |
| 全大写 + 下划线，2～5 个词，最多 6 个 | `CPI_YOY`、`PMI_MANU` |
| 公认缩写直接用，不加后缀 | `DR007`、`XAUUSD`、`BRENT_CRUDE`（不写 `BRENT_CRUDE_FUTURES_CLOSING_PRICE_USD_BBL`） |
| 调整方式写进 ID | 同比 `_YOY`、环比 `_MOM`、累计同比 `_CUM_YOY`、年度目标 `_ANNUAL` |
| 频率转换不写进 ID | 「由日度转月度」是 ETL 元数据，不是指标定义 |
| 词序：主体 + 细分 + 调整 | `LOCAL_SPECIAL_BOND_TARGET_ANNUAL` |
| 不为改而改 | 原代码已规范则直接采用 |

另配一份极简中文显示名，供模型输出时使用（如 `TSF_STOCK_YOY` → 社融存量同比，`GOV_EXPEND_CUM_YOY` → 财政支出累计同比），避免报告里出现英文代码。

### 3.2 两轮独立推理 + 一致性校验

- Round 1：完整推理，输出推荐 ID、备选、中文显示名、命名理由、自评置信度（提示词原件：`appendix/prompts/reverse-id-round1.txt`）。
- Round 2：全新上下文、不同系统提示词，只输出推荐 ID、备选、置信度（`reverse-id-round2.txt`）。
- 比较器判定一致性：
  - **high**：完全一致；或经缩写等价（MANU=MANUFACTURING、INFRA=INFRASTRUCTURE、INVEST=INVESTMENT、GOV=GOVERNMENT、CUM=CUMULATIVE、YTM=YIELD）后一致；或只差一个可选修饰词（YIELD／INDEX／RATE／PRICE／FUTURES／CLOSE／SETTLE）且共享 ≥2 个核心词。
  - **medium**：词集 Jaccard ≥ 0.6，或互为子串，或一轮推荐出现在另一轮备选中。
  - **low**：其余，必须人工复核。
- 最终置信度 = (R1 自评 + R2 自评 + 一致性) / 3，≥2.5 high、≥1.5 medium。

**局限**：两轮是同一模型、共享同一批示例（`XAUUSD ✓`、`DR007 ✓` 等），一致更多反映示例约束下的自洽，而不是模型真正理解。更有效的验证是**往返测试**：只把 ID（加单位）交给另一模型，让它还原中文含义与口径，能还原才算合格。

## 4. 喂数格式

### 4.1 长表 CSV，七个字段

```csv
indicator_id,ref_month,value,unit,adjustment,source,data_type
CPI_YOY,2026-02,0.6,%,YoY,NBS,Inflation
DR007,2026-03,1.45,%,Level,CFETS,Rate
SPECIAL_BOND_PROGRESS,2025-05,37.13,%,Derived,Derived,Fiscal
```

- 一行一个指标一个月；`value` 只放最终月度值。
- 月均／月末等口径在**定义层**一次性说明（提示词开头的口径段），不拼进 ID，也不在每行重复；只有同一指标确需同时喂两种口径时才加字段区分。
- 按 schema（`appendix/data/data-type.csv`）的板块顺序与板块内顺序拼接，每块一个 `## 板块名` 加一个 csv 代码块。
- 时间窗：最近约 16 个月（原项目取 2024-11 起）。

### 4.2 月报提示词骨架

完整实例（含数据）见 `appendix/prompts/市场分析-提示词模板-v4.md`。

```text
# 任务目标        撰写《YYYY年M月中国市场与外部宏观环境分析报告》，覆盖四大类资产驱动
## 语言风格       专业且可读，面向客户
# 角色            银行投顾项目组的投资顾问，兼具宏观策略与量化分析
# 约束条件        1. 结论只基于给定数据；不足时写「无法从当前数据中确定」
                  2. 不给具体比例与组合方案，只给方向性判断及驱动逻辑
## 月频口径说明   哪些指标是日转月均，其余按原月度口径
# 宏观经济数据    12 个板块的长表 CSV
# 新闻数据        5 条加工后的重点事件（schema 见 04）
## 市场表现参考   A 股三大指数起止点位，并限定「不扩展至未提供指数」
# 四大类资产长期风险收益结构基准
                  资产定义 → σ → Σ → ρ → 季度国债 1Y/10Y/期限利差 → 1Y/3Y/5Y 收益/波动/Sharpe 画像
```

### 4.3 报告应答结构（PRD）

| 章节 | 必要要素 | 可选要素 |
| --- | --- | --- |
| 整体市场结构：宏观周期定位 | 复苏／过热／滞胀／衰退象限 | 库存周期、信用周期、技术长波 |
| 整体市场结构：动能拆解 | 消费、投资（基建／制造／地产）、出口 | 上中下游景气扫描 |
| 整体市场结构：货币与财政 | 央行操作、财政政策 | 政策利率、存单、专项债进度、城投净融资等 |
| 整体市场结构：国际环境 | 美联储、地缘、大宗、跨境资金 | 布油、铜、黄金、外储 |
| 整体市场结构：风险预警 | 系统性风险与坏情形 | — |
| 大类资产驱动 | 股票／固收／另类／现金各自的事件与表现 | 客户持仓 |
| 后续关注 | 宏观追踪、资产调整、风险提示 | 社融、PMI 新订单、地产销售、剪刀差、出口等 |
| 总结 | 关键风险：最大风险点、预警指标、止损建议 | 3 条核心结论、3 个跟踪变量 |

## 5. 测评闭环（生成 → 评测 → 优化）

```text
当前提示词 + 市场数据 → 生成模型（qwen3-235b）→ 3 条测试查询的回答
→ 评测模型（Claude，开启深度思考）按 7 维打分并分析「提示词设计缺陷」
→ 加权分 ≥ 7.5 停止；否则评测方针对薄弱维度改写提示词 → 下一轮（最多 5 轮）
→ 保存每轮提示词、得分、改动摘要与历史最优版本
```

| 维度 | 权重 | 要点 |
| --- | --- | --- |
| 结构完整性 | 20% | 是否覆盖规定模块 |
| 数据引用准确性 | 20% | 引用数字与输入完全一致，无捏造 |
| 分析深度 | 20% | 因果推断与前瞻判断，宏观—中观—微观贯通 |
| 结论明确性 | 15% | ≤3 句给出方向 + 置信度 + 核心依据 |
| 操作可行性 | 10% | 原版要求方向／仓位／时间／重点与规避板块（与月报约束冲突，见 `06`） |
| 专业性 | 10% | 事实与判断分开 |
| 风险提示 | 5% | 每个风险附具体名称与日期 |

多评测器集成：Claude 之外可启用豆包、DeepSeek-V3／R1、Qwen-Max／Plus；每维取加权平均，以评测器间标准差判断分歧（<0.8 可信，0.8～1.5 参考原始理由，>1.5 人工复核）。

可复用的是**骨架**（版本化提示词、结构化评分、分歧度量、断点续跑）；评分维度须按新任务重写，并用真实数据而非虚构样例评测。
